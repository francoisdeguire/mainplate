The feature this tested was cut. mainplate does not render consumer HTML inside the SVG. This page is a record of what was found, not a specification — nothing implements from it. The recipe below does work, and is kept because it is the answer to "can HTML go inside an SVG, and what does it cost". The supported way to put HTML on a face is layer composition outside the SVG: stacked absolutely-positioned <Mainplate> roots in a shared relative container with HTML between them. See fixtures/README.md for the full reasoning.

Every SVG here is viewBox="-110 -110 220 220" sized by width and height attributes at 320 px, so one user unit is 320/220 screen pixels and the counter-scale is k = 220/320 = 0.6875.

The rule this whole file is built around: in Safari, any descendant of a <foreignObject> that acquires a RenderLayer — anything positioned, transformed, with opacity < 1, or filtered — is reparented into the SVG root's layer, so the viewBox transform never reaches it and the content lands far off the dial. WebKit bug 23113, open since 2009. SVG 2 says Safari is wrong; the real fix (LBSE) has landed but is not the default, so nothing should be planned around it. The recipe below routes around the bug by creating no layers at all: positioning by SVG x/y attributes, sizing by zoom, centring by display: grid.
